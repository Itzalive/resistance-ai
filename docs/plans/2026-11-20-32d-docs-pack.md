# Architecture Docs: the AI Pack Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use resistance-engine:subagent-driven-development (recommended) or resistance-engine:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `architecture-docs build` also writes the rest of the AI pack: `pack/README.md` (layout, index, facts outside any area), `pack/areas/<name>.md` and `pack/capabilities/<name>.md`, in the pack's raw text form.

**Architecture:** This repository has no architecture model. New modules in `skills/shared/scripts/architecture-docs/`: `pack-text.mjs` (the pack text rules and the file frame), `pack-blocks.mjs` (element, record, known-gap and step blocks, with the pack-file suffix) and `pack.mjs` (the slices, the index file and the set of pack files). `facts.mjs` gains the selections the area and capability documents share with the pack (`areaRecords`, `capabilityRecords`, `outsideAreas`); the overview moves onto `outsideAreas`. `build.mjs` adds the pack files to the build.

**Tech Stack:** Node ESM, pytest.

**Spec:** `docs/superpowers/specs/2026-11-17-architecture-docs-design.md`, "Writers" (Pack text), "What each document holds" (Shared rules, Area for the area's records, AI pack with its Pack layout, Index, element block, record blocks, known-gap and step lines), AC-24, AC-25, AC-26, and the pack parts of AC-9, AC-12, AC-13 and AC-17 — decisions applied: none. The pack format was settled by the owner on 2026-11-20 in two spec amendments (commits `eef795c` and `878e2b8`) before this plan. This is plan 2c of plan 2's three (2a the tool core, 2b the writers and the overview). The area and capability documents are plan 3; their selections (`areaRecords`, `capabilityRecords`) are built here, first used by the pack.

**Open decisions:** none. The pack's exact text (suffix position, one-line and multi-line fields, separators, empty list fields, a contract with no compatibility rule, empty index kinds, order within sections) is settled in the spec by two owner-approved amendments of 2026-11-20 (`eef795c` and `878e2b8`); the tasks apply them.

**Size:** 8 tasks, 2 entry paths (`build`, `check`), 1446 lines (reported, not a target)

**Trust boundary:** changed — see Trust-boundary table. No new file writes: only `writer.mjs` writes, and the safety tests (`tests/scripts/test_architecture_docs_safety.py`) scan every new module unchanged. No comment or string in a docs module may hold a forbidden call name followed by `(` (the scan reads whole files): the names `write`, `link`, `rm`, `cp`, `rename`, `mkdir`, `unlink`, `truncate` and the others in `CHANGES_FILES` must not be followed by an opening bracket anywhere in the new modules. The new output is where model and record text reaches agents that read the pack raw: the pack text rules are its only defence, by the spec's choice.

### Risk & Confidence Assessment

**Confidence:** 90% — the pack format is exact in the amended spec and every line form has an exact-text test; the selections are filters over the export.

**Complexity Risk:** Medium — the pack-file suffix: every id printed in a slice must be checked against that slice's held set, in every line form (uses, used by, runtime, bound by, owner, bound, binds, decisions, capabilities, superseded_by, known-gap ends, step ends).

**Environmental Risk:** Low — no new dependency, no new file write, no subprocess.

**Unknown variables:**
- None in the repository: the dry run built every task from this plan's code blocks and passed. What stays unverified is the executor's transcription: a test or code block copied with a changed escape (`\\#`, `\\n`) fails its exact-text assert, which is the intended signal.
- Whether agents reading the pack need more than the spec's line guard (the known limit below); it is the spec's choice and not tested beyond it.

**Main failure modes:** an id printed without its suffix, or with one it should not have (each line form has a test with a held and a not-held id); a multi-line field written with a line that starts a heading or a separator (each multi-line field has a test); the plan 2a and 2b tool tests that list the output files (sweep rows); a module comment that names a forbidden call (the safety test fails the commit).

**Known limit, not a plan decision:** the spec's pack text rule guards a line that *starts* with `#` or `---`. A line indented by up to three spaces before `#`, or a `===` line under text, is still a Markdown heading to a renderer. The pack is read raw by agents, which is why the spec chose this rule; the plan implements it as written and does not widen it.

// Pack text (spec, Writers, Pack text): the pack is read raw by agents, so ids and text are written as `export` gives
// them, unescaped. A one-line field loses its line feeds; in a multi-line field every line is kept, and a line
// starting with `#` or `---` gets a leading `\`, so record text cannot start a heading or a separator.
import { MARKER } from './out.mjs';

export const oneLine = (text) => String(text).replace(/\n/g, ' ');

const GUARDED = /^(#|---)/;
export const multiLine = (text) => String(text).split('\n').map((line) => (GUARDED.test(line) ? `\\${line}` : line)).join('\n');

// Spec, Pack layout: the marker line, `# <title>`, then the file's parts (headings, paragraphs and blocks of lines),
// one blank line apart, ending in one line feed.
export function packFile(title, parts) {
  return `${[MARKER, `# ${oneLine(title)}`, ...parts].join('\n\n')}\n`;
}
```

// Spec, Area: an area's records: the decisions binding an area element (cross-cutting first, then by id), the
// contracts whose owner or bound elements are in the area, the open questions binding area elements, and the
// known-gap entries with an end in the area, sorted by pair.
export function areaRecords(data, gap, area) {
  const inArea = new Set(area.elements);
  const touches = (ids) => ids.some((id) => inArea.has(id));
  const decisions = data.decisions.filter((decision) => touches(decision.binds))
    .sort((x, y) => Number(isCrossCutting(y)) - Number(isCrossCutting(x)) || cmp(x.id, y.id));
  return {
    decisions,
    contracts: data.contracts.filter((contract) => touches(recordElements('contracts', contract))),
    holes: data.holes.filter((hole) => touches(hole.binds)),
    gap: gap.filter((entry) => inArea.has(entry.from) || inArea.has(entry.to))
      .sort((x, y) => cmp(x.from, y.from) || cmp(x.to, y.to)),
  };
}

// Spec, Capability and AI pack: the elements a capability's steps touch (sorted), and the decisions and contracts
// whose `capabilities` name it.
export function capabilityRecords(data, capability) {
  const names = (record) => (record.capabilities ?? []).includes(capability.name);
  return {
    elements: [...new Set(capability.steps.flatMap((step) => [step.from, step.to]))].sort(cmp),
    decisions: data.decisions.filter(names),
    contracts: data.contracts.filter(names),
  };
}
```

// The pack's blocks (spec, AI pack): the element block, record blocks, known-gap lines and step lines. Every id not
// held in the slice being written is followed by its pack file in brackets: the first area's slice, or README.md for
// a fact outside any area; a capability's pack file is its own slice. `ctx` comes from `packContext`.
import { cmp } from '../architecture-delta/report.mjs';
import { areasByElement, areasOf, isCrossCutting, recordElements } from './facts.mjs';
import { oneLine, multiLine } from './pack-text.mjs';

export const PACK_INDEX = 'README.md';
export const packArea = (name) => `areas/${name}.md`;
export const packCapability = (name) => `capabilities/${name}.md`;

const KINDS = ['elements', 'decisions', 'contracts', 'holes', 'capabilities'];
// `held`: the ids a slice holds in full, as lists per kind (a missing kind holds none).
const heldSets = (held) => Object.fromEntries(KINDS.map((kind) => [kind, new Set(held[kind] ?? [])]));

export function packContext(data, held = {}) {
  return {
    data,
    byElement: areasByElement(data),
    elements: new Map(data.elements.map((element) => [element.id, element])),
    records: {
      decisions: new Map(data.decisions.map((record) => [record.id, record])),
      contracts: new Map(data.contracts.map((record) => [record.id, record])),
      holes: new Map(data.holes.map((record) => [record.id, record])),
    },
    held: heldSets(held),
  };
}

// The same context for another slice: the maps are kept, only the held sets change.
export const withHeld = (ctx, held) => ({ ...ctx, held: heldSets(held) });

// An id that names nothing in the model fails the build (exit 2, `internal`): the records and the known-gap file are
// checked on load, so it can only be a fault in the tool.
function packFileOf(kind, id, ctx) {
  if (kind === 'capabilities') return packCapability(id);
  const record = kind === 'elements' ? null : ctx.records[kind].get(id);
  if (kind === 'elements' ? !ctx.byElement.has(id) : record === undefined) throw new Error(`${id} is not in the model`);
  const areas = kind === 'elements' ? ctx.byElement.get(id) : areasOf(recordElements(kind, record), ctx.byElement);
  return areas.length > 0 ? packArea(areas[0]) : PACK_INDEX;
}

// Spec, AI pack: the suffix follows the id and the parenthetical that belongs to it.
export function ref(kind, id, ctx, note = '') {
  return ctx.held[kind].has(id) ? `${id}${note}` : `${id}${note} [${packFileOf(kind, id, ctx)}]`;
}

const refs = (kind, ids, ctx) => ids.map((id) => ref(kind, id, ctx)).join(', ');

function runtimeLines(id, ctx) {
  const byOther = (x, y) => cmp(x.other, y.other) || cmp(x.link.kind, y.link.kind);
  const outgoing = ctx.data.runtime.filter((link) => link.from === id).map((link) => ({ arrow: '->', other: link.to, link })).sort(byOther);
  const incoming = ctx.data.runtime.filter((link) => link.to === id).map((link) => ({ arrow: '<-', other: link.from, link })).sort(byOther);
  return [...outgoing, ...incoming].map(({ arrow, other, link }) => {
    const detail = [link.kind, ...link.titles.map((title) => `"${oneLine(title)}"`)].join(', ');
    return `runtime: ${arrow} ${ref('elements', other, ctx, ` (${detail})`)}`;
  });
}

// Spec, AI pack, element block: a line or a `·` part with nothing to show is left out.
export function elementBlock(id, ctx) {
  const element = ctx.elements.get(id);
  const head = [`kind ${element.kind}`];
  if (element.tags.length > 0) head.push(`tags ${element.tags.map((tag) => `#${tag}`).join(' ')}`);
  if (element.code.length > 0) head.push(`code ${element.code.join(', ')}`);
  if (element.rules.length > 0) head.push(`rules ${element.rules.join(', ')}`);
  const lines = [`### ${id}: ${oneLine(element.title)}`, head.join(' · ')];
  if (element.description !== null) lines.push(multiLine(element.description));
  const uses = [...new Set(ctx.data.allowed.filter((entry) => entry.from === id).map((entry) => entry.to))].sort(cmp);
  const usedBy = [...new Set(ctx.data.allowed.filter((entry) => entry.to === id).map((entry) => entry.from))].sort(cmp);
  if (uses.length > 0) lines.push(`uses: ${refs('elements', uses, ctx)}`);
  if (usedBy.length > 0) lines.push(`used by: ${refs('elements', usedBy, ctx)}`);
  lines.push(...runtimeLines(id, ctx));
  const boundBy = ctx.data.decisions.filter((decision) => decision.binds.includes(id))
    .map((decision) => ref('decisions', decision.id, ctx, isCrossCutting(decision) ? ' (cross-cutting)' : ''));
  if (boundBy.length > 0) lines.push(`bound by: ${boundBy.join(', ')}`);
  return lines.join('\n');
}
